# 网格撤单一致性修复（2026-09-11）

## 修改范围

- `GridEngine` 新增统一的撤单确认方法：撤单请求成功后再次查询订单；只有状态确认为 cancelled、没有未入账成交且本地持久化成功时，才将旧订单移出跟踪并允许替换。
- 客户端不可用、撤单超时、查询失败、非终态回报、撤单期间成交、本地状态保存失败时，保留原订单供后续成交同步处理。
- 入场/退出订单去重、退出覆盖改量、按持仓方向撤单、整体撤单均使用同一确认路径。
- 停机不再直接将所有本地订单批量标为 cancelled；只释放已确认终止订单对应的工作状态。
- 定时退出覆盖检查重试此前失败的改量，而不是看到旧退出单存在就永久跳过。
- `GridRestingOrderRepository.update_status` 返回更新是否成功，避免数据库失败后继续发替换单。

不修改云端、不自动改写数据库中的用户策略、不清理历史订单、不触发实盘策略启动。此前工作区其他修改保持原样。
